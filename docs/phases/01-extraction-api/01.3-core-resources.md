# 01.3 — Core resources

## Goal

Expose only resources with a demonstrated near-term consumer.

## Candidate sequence

1. `/health` and source status
2. `/game`
3. `/squad`
4. `/players/{id}` for a known, visible player
5. `/clubs/{id}` for known clubs
6. `/fixtures` for the controlled club
7. `/competitions/{id}` only when fixture semantics require it

Each endpoint addition requires:

- a Python use case;
- an allowlisted DTO;
- visibility classification for every field;
- a sanitized contract fixture;
- missing/stale entity behaviour;
- ordering and collection-size decisions.

## Exit criteria

- `/game`, `/squad`, and the Phase 02 ingestion resources are sufficient for
  their documented consumers.
- Unused speculative fields and endpoints are absent.
- Entity relationships use stable IDs and do not require nested object graphs.
