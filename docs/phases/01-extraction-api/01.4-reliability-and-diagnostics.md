# 01.4 — Reliability and diagnostics

## Goal

Make local operation understandable without exposing sensitive or hidden data.

## Work

1. Add structured source status to health reporting.
2. Use correlation IDs and structured logs for a request path.
3. Report game/framework compatibility without dumping memory contents.
4. Define request timeouts, retry ownership, and rate limits for local polling.
5. Convert known extraction failures into stable error codes.
6. Ensure one failed read does not terminate the service.
7. Bind to loopback by default and document the implications of changing it.

## Operational checks

- no game process;
- game open without a save;
- save loading or advancing;
- stale object/pointer;
- incompatible build;
- malformed fixture;
- Python client timeout.

## Exit criteria

- An operator can distinguish all checks above from logs and health output.
- Diagnostics never include hidden values, bulk entity dumps, or raw memory.
- Recovery instructions are documented for every expected degraded state.
