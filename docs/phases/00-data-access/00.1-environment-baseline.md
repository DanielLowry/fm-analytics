# 00.1 — Environment baseline

## Goal

Make a failed or successful experiment reproducible before integrating the
memory reader into the bridge.

## Work

1. Record the host, compatibility layer, and architecture.
2. Record the FM20 executable version, distribution, database, loaded editor
   data, and save-game date.
3. Select and pin the extraction framework commit or binary checksum.
4. Record the required .NET SDK/runtime and CPU architecture.
5. Build and run the framework's smallest existing example without modifying
   this repository's bridge.
6. Create a sanitized test-save description: human manager, club, expected
   date, and a few expected squad members.
7. Record setup commands and any native-library requirements.

## Deliverables

- A version matrix added to this document after the experiment
- A pinned dependency acquisition method
- Build/run instructions usable after a clean checkout
- A short list of known incompatibilities

## Exit criteria

- A second run from a clean terminal reaches the same result.
- No dependency is described only as “latest.”
- Failure on an unsupported configuration is distinguishable from a coding
  defect in FMBridge.

## Findings

Initial Linux/Proton probe executed on 9 September 2026:

| Component | Observed value |
| --- | --- |
| Host | Linux Mint 22.3, x86-64 |
| Kernel | `7.0.0-30-generic` |
| Steam app | `1100600` |
| Steam build ID | `5594386` |
| FM executable | PE32+ x86-64, 532,226,560 bytes |
| Compatibility layer | Proton Experimental `experimental-11.0-20260903c-x86_64` |
| Proton prefix | `/games/SteamLibrary/steamapps/compatdata/1100600/pfx` |
| FMScoutFramework reference | AppCakeLtd commit `9fb3904` (`FMSE20 Final`) |
| Executable product version | `20.4.4-1442341` |
| Matching framework profile | `20.4.4-1442341`, Steam Windows |

The AppCakeLtd repository currently ends at FM22, but its Git history contains
the final FM20 definitions. It does not currently show a license file, so its
source must not be copied into this project until reuse terms are clarified.
Offsets and behaviour can guide clean, minimal interoperability experiments.

The running Proton process exposed the Windows `fm.exe` image at module base
`0x140000000`. Opening `/proc/<pid>/mem` read-only and reading mapped bytes
succeeded with host `kernel.yama.ptrace_scope=1` in this environment.

The executable's embedded `FileVersion` and `ProductVersion` strings independently
confirmed `20.4.4-1442341`; the profile selection is therefore not based only
on a plausible decoded date.

The probe also checks the mapped executable's exact observed size
(`532,226,560` bytes) before applying the pinned offsets. A mismatch is an
explicit incompatible-build failure. This is intentionally strict: another FM
patch needs its own reviewed profile.

The repository pins .NET to the latest installed .NET 8 feature band through
`global.json`. The clean validation used SDK `8.0.425`, Python `3.12.3`, and:

```bash
dotnet restore src/FMBridge/FMBridge.csproj
dotnet build src/FMBridge/FMBridge.csproj --configuration Release --no-restore
python3 -m unittest discover -s tests -v
```

The build completed with zero warnings and zero errors. The Python suite passed
all 40 tests, including project configuration and source-file line caps. CI
runs the same build on .NET 8 and the Python suite on the pinned Python matrix.

Known incompatibilities are non-x86-64 hosts, native Linux FM builds, non-Steam
executables, and any FM executable whose size does not match the recorded final
20.4.4 Steam build. The Linux process must also be readable under the host's
`ptrace` policy.
