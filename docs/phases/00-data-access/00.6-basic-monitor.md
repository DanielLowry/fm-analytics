# 00.6 — Basic live monitor

## Goal

Provide an intentionally small local interface early, so extracted fields can
be inspected, refreshed, and downloaded without waiting for the eventual
polished dashboard.

## Current interface

Run:

```bash
python3 tools/fm20_monitor.py
```

Then open `http://127.0.0.1:8765`. The page shows source status, in-game date,
active human manager, controlled club, first-team squad basics, source/adapter
information, and observation time. The squad table includes age, position,
condition, match fitness, availability, and a compact contract/loan summary. It
refreshes every 30 seconds and offers the underlying JSON at `/api/status`. A
smaller export is available at `/api/squad`, with `.json?download=1` variants
and buttons for both documents.

The server binds to loopback by default and has no third-party dependencies.
It uses FMBridge at `http://127.0.0.1:5072` by default, keeping memory traversal
out of the UI. `--direct` remains available only as a diagnostic fallback.

The `/attributes` diagnostic page integrates the standalone Phase 03 proof
source. Its default in-game mode lists only the managed first team and can query
either that team or one selected player. Full visibility requires a separate
selection and acknowledgement before it enables the loaded-team search. Full
responses carry an `underlying-exact-not-manager-visible` guarantee and warning;
they remain outside the bridge, persistence, and analytics boundaries. This
deliberate comparison mode exists to verify extraction, not to inform play.

The first live verification served HTTP successfully and rendered the expected
responsive page in a headless browser. After active-manager selection and FM
string decoding were corrected, the API resolved Hungerford Town and returned
17 first-team player identities with position labels.

The bridge-backed version was then verified against the live save: status,
date, club, all 17 players, positions, fitness, availability, and loan context
rendered successfully. The monitor remains responsive when its source returns
an unavailable state, and its exports are projections of the approved bridge
contract.

Optional-field failures are represented as `null` or `unknown` in the table;
whole-source failures use the structured health status and detail. Polished
navigation, persistence, charts, and analytics remain Phase 11 work.

## Exit criteria

- The page remains useful when FM is unavailable and shows a clear state.
- Refreshing reflects an advanced in-game date.
- Downloaded JSON contains only approved manager-visible fields.
- UI code contains no extraction or analytics decisions.
