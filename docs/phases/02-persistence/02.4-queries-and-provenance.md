# 02.4 — Queries and provenance

## Goal

Provide a narrow read layer that can explain where every value came from.

## Initial queries

- latest successful capture for a save;
- squad as observed at a capture;
- player attribute observation as of a capture;
- player attribute/visibility history;
- captures between two in-game dates;
- changes between two captures;
- failed or partial captures requiring inspection.

Every returned observation should be traceable to save, capture, source build,
API contract version, in-game date, and wall-clock time.

## Exit criteria

- Query tests demonstrate that unknown, absent, and unchanged remain distinct.
- Results are domain objects/read models rather than arbitrary SQL tuples.
- Analytics callers do not need to know table layout.
