# 02.3 — Snapshot importer

## Goal

Capture a coherent set of bridge resources transactionally and idempotently.

## Work

1. Request game context first and establish save/capture identity.
2. Read the configured resource set with bounded failure handling.
3. Reject responses whose game context changes during capture, or mark them
   partial according to the approved consistency policy.
4. Validate domain and visibility invariants before opening the write path.
5. Write one transaction per accepted capture.
6. Calculate a deterministic fingerprint for idempotency.
7. Record partial/failed capture metadata without presenting it as observed
   absence.

## Exit criteria

- Reimport is safe after retry or process interruption.
- An invalid resource rolls back or marks the capture partial as designed.
- Fixtures cover unchanged state, one changed attribute, membership change, and
  bridge failure.
- Import contains no football ranking or recommendation logic.

## Initial implementation

The explicit CLI option `--snapshot-db PATH` captures the already validated
game and squad domain objects in one transaction. Identical content reuses the
existing capture; a changed visible observation creates a new one. Tests cover
round-trip reconstruction, idempotency, changed condition, incoherent dates,
and timezone-aware capture provenance.

Multi-resource retry metadata and partial captures remain deferred because the
MVP uses a manually triggered game/squad capture and rejects incoherence rather
than persisting a partial recommendation input.
