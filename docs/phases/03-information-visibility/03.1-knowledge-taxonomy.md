# 03.1 — Knowledge taxonomy

## Goal

Define the entity-discoverability and field-knowledge states an analytics
consumer can rely on.

## Entity discoverability

Classify how a player may enter an analytics collection, for example:

- controlled-club membership;
- visible in the manager's player search;
- known through a scouting assignment or report;
- visible through an approved competition/opposition context;
- not discoverable;
- collection status unavailable because extraction failed.

The final taxonomy must follow observed FM20 behaviour rather than assuming
these candidate categories are mutually exclusive. Every included external
player retains an inclusion reason and observation time. Discoverability does
not imply that every field is known.

## Candidate states

| State | Meaning |
| --- | --- |
| Known | The manager sees a specific value now |
| Range | The manager sees an inclusive interval now |
| Unknown | The field is conceptually relevant but no value is visible |
| Unavailable | The source could not establish the observation |
| Not applicable | The field does not apply to this entity/context |
| Stale | Previously observed information has an in-game age |

The first three already exist for attributes. This subphase determines whether
the remaining states belong in the attribute contract, surrounding metadata,
or capture status rather than adding enum members mechanically.

## Field classes to classify

- player attributes and positions;
- age/date of birth and nationality;
- contract, value, wage, and transfer availability;
- personality and media description;
- injuries, suspensions, fitness, and match sharpness;
- scout recommendation, pros/cons, and report age;
- club, competition, fixture, and match information.
- player-search membership, scouting relationship, and inclusion provenance.

## Exit criteria

- Every Phase 04–06 candidate input has a state model and visibility owner.
- Unknown and extraction failure cannot be confused.
- Policy says how report age and outdated knowledge are represented.
- Collection membership cannot be inferred merely from the existence of an FM
  object, and missing membership cannot be confused with extraction failure.
